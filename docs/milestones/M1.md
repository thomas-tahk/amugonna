# Milestone 1: Cook from my pantry

**Done-gate:** "On my phone or my computer I put what's in my fridge and pantry into Amugonna, and within seconds of finishing I see recipes I can make with it, open one, and cook the meal from that screen."

**Status:** passes in automated runs at phone (390x844) and desktop (1280x800) sizes against the real server and database. You have not tried it yet.

- **Speed:** "Cook now" shows 100–330 ms after you tap "See what I can cook" (e2e log, both sizes). Free text is checked in about 145 ms. With 98 pantry items, Kitchen loads in about 180 ms and Cook in about 140 ms (final QA pass).
- **Real recipe base:** a full TheMealDB import ran in GitHub Actions (this sandbox can't reach themealdb.com): **790 recipes**, 0 failures. **97.0%** of ingredient lines (8,090 of 8,336) are recognised by our ingredient vocabulary. Results for three reference pantries ([details](../chief/research/mealdb-live-2026-10-28.md)):

  | Pantry | Cook now | 1 ingredient away |
  |---|---|---|
  | 8 basics (eggs, rice, onion, garlic, chicken, pasta, tinned tomatoes, cheddar) | 0 | 14 |
  | + butter, milk, flour, sugar, lemon, potato, carrot, bread (16) | 8 | 51 |
  | well stocked (34) | 24 | 69 |
- **No false "you have it":** the final QA pass checked every "Cook now" recipe for 5 different pantries ingredient by ingredient and found no recipe recommended that you can't make. Substitutions are always shown ("using parmesan for feta").
- **Tests at the head:** server 679 and client 95 unit/integration tests; 4 Playwright specs (done-gate, Cook-tab race, CTA count under slow network, phone confirm tap) on phone and desktop sizes — 7 runs green, the phone-only one skipped on desktop; GitHub CI (unit + e2e) green on the final head ([run 40684217817](https://github.com/thomas-tahk/amugonna/actions/runs/40684217817)).

**Scorecard so far:** [`docs/chief/scorecard.md`](../chief/scorecard.md). First-pass reviews 0/9 (every reviewed issue needed a fix round), merged/planned 10/10 plus 2 added (0 stuck). Escaped bugs and guesses kept get filled in after you play it.

## How to try it

On your Mac, from the repo:

```bash
git fetch && git checkout m1-cook-from-pantry
npm ci
# server/.env needs DATABASE_URL, DIRECT_URL, JWT_SECRET (see server/.env.example).
# Point it at a LOCAL database for trying this, not the live one.
cd server && npx prisma migrate deploy && npm run seed
npm run import:mealdb        # optional but recommended: ~790 real recipes, about 1 minute
cd .. && npm run dev
```

Open the address Vite prints (usually http://localhost:5173), on your computer or on your phone on the same Wi-Fi (use your Mac's IP). Then:

1. Sign up.
2. **Kitchen:** tap what you have in the quick picks, or type a line like `eggs, leftover rice, half an onion, spinach, parmesan` and tap **Check**. Remove any chip that's wrong, then tap **Add**.
3. Tap **See what I can cook (N)**.
4. **Cook:** pick from "Cook now", or from "1 ingredient away" (it names the missing item).
5. In the recipe, missing items are at the top with **Copy missing items**. Tap a step to tick it off. The screen stays awake while the recipe is open.

Without the import you only get the 21 starter recipes plus 30 "Amugonna test fixture" recipes, which the dev seed adds so the tests have data. `NODE_ENV=production npm run seed` leaves the test recipes out.

Watch for:
- Whether the things you actually keep are recognised when you type them. Unknown items get a yellow **new** badge.
- Whether "Cook now" ever suggests something you can't actually make. That is the bug that matters most.
- The look (paprika red, herb green, amber, near-black on warm off-white), and the bottom tab bar on your phone.

- My recipes hung on a spinner ([#17](https://github.com/thomas-tahk/amugonna/issues/17)).
- The old ingredient search route showed other users' typed items to anyone, without sign-in.
- Tests could write into whatever database `server/.env` pointed at. They now only run against a database whose name contains "test".
- The server now refuses to start without `JWT_SECRET`.
- From QA: the phone confirm panel's Add button was covered by the sticky bar ([#16](https://github.com/thomas-tahk/amugonna/issues/16)); keyboard focus ring and focus moves ([#18](https://github.com/thomas-tahk/amugonna/issues/18), [#19](https://github.com/thomas-tahk/amugonna/issues/19)); visible error toasts ([#21](https://github.com/thomas-tahk/amugonna/issues/21)); sign-in again on an expired session ([#22](https://github.com/thomas-tahk/amugonna/issues/22)); tabs and recipes have URLs, so Back and reload work ([#23](https://github.com/thomas-tahk/amugonna/issues/23)); plain-language errors ([#24](https://github.com/thomas-tahk/amugonna/issues/24)); slimmer image placeholder ([#25](https://github.com/thomas-tahk/amugonna/issues/25)).

**Cut from M1, and why:**
- **Wikibooks Cookbook import:** free-form wikitext needs a parser and hand review, and the sandbox can't reach wikibooks.org. At 97% recognition on 790 recipes it isn't urgent.
- **Dietary/allergy filters:** M2. One known gap: chicken stock counts as a swap for vegetable stock.
- **Photo-to-pantry, AI, bring-your-own import, deploy:** later milestones, per your answers.

**Known, not fixed:**
- An 8-item pantry of pure basics finds nothing to cook *right now* in the real catalogue (most recipes also need butter, milk, herbs and so on), but 14 recipes are 1 away. Matching is deliberately strict: tinned tomatoes don't count as fresh, and ground beef doesn't count as steak. See decision 3.
- `server/src/lib/ingredients/vocabulary.ts` is hand-curated; about 3% of real ingredient lines are still unknown (vague ones like "seasoning", "starch", "fruit mix").
- No rate limiting on sign-in or sign-up yet. Any signed-in user can publish a public recipe, which then shows in everyone's Cook results. Both are M2.
- The `mealdb-live` workflow only runs from the milestone branch until this merges. After that, it runs weekly and on demand from main.
- Tested in Chromium with phone emulation, not on a real iPhone or Safari.
- The leftover branch `m1-live-probe` (a measurement run) is still on GitHub. The sandbox couldn't delete it; you can delete it.

**Stuck:** none.

**Recipe source, in one line:** bulk-scraping recipe sites into a public app is legally risky, so the base is TheMealDB's free catalogue, imported with attribution into your own database by a script and never committed to git. Social-media and URL recipes come later as each user's own "bring your own" import, never redistributed.

## Decisions that need you (most important first)

1. **Before you merge: run one command against the live database.** It was created with `db push`, so the first deploy after merge (Render runs `prisma migrate deploy`) fails unless you first run `npx prisma migrate resolve --applied 20260101000000_init` with the live `DATABASE_URL`. Then merge, then `NODE_ENV=production npm run seed` against it. The exact order is in [`server/setup-database.md`](../../server/setup-database.md). I tested it on a copy of a db-push database, and pantry rows survive. Alternatively, don't merge until you've picked a host (decision 2).
2. **Pick a host.** None of these sleep when idle. Prices are from third-party 2026 summaries, so confirm them:
   - **Railway Hobby:** $5/month minimum including $5 of usage. App plus Postgres realistically ~$5–20/month. Least setup.
   - **DigitalOcean** (your original choice): a ~$6/month droplet running app and Postgres yourself; or App Platform (~$5) + Managed Postgres (~$15) for no server upkeep.
   - **Render paid:** Starter web (~$7/month) + paid Postgres (~$6/month+). The free tier sleeps and its Postgres expires, so not that.

   My pick: **Railway** for now (cheapest with no server upkeep); move later if it grows.
3. **How strict should "Cook now" be?** I built it strict:
   - **Always assumed:** water, salt, black pepper and cooking oil.
   - **Everything else must be in your kitchen.** Tinned tomatoes ≠ fresh. Swaps within a family (cheddar for parmesan) count, but are labelled.

   The cheap alternative is a short "I always have these" list you tick once, for example butter, milk, flour, sugar and dried herbs. In the real catalogue that moves a basic kitchen from 0 to about 8 cook-now recipes. Keep strict, or add the list in M2?
4. **TheMealDB key.** The free key "1" is for development and education; third-party summaries say a public or app-store release needs a supporter key (reported as about £10 one-off or a small Patreon). I couldn't open their terms page from the sandbox. Before any public launch, read https://www.themealdb.com/terms_of_use.php and buy the key if it says so. Nothing to do while it's just you.
5. **The look.** Paprika-red primary, herb green for "have", amber for "1 away" and swaps, near-black on warm off-white, and a bottom tab bar on phones. Screenshots are in [`m1-evidence/`](m1-evidence/) (`e2e-phone-*.png` are real runs). Keep or redirect?
6. **Revoke the old OpenAI key** in your local `server/.env` (flagged in the first audit). No code uses it, and M1 needs no API keys.
